Camera

Class for managing display and rendering of elements in a canvas.

📝 Description

The Camera class is the heart of the JSGE rendering system. It allows you to define a viewing area within a canvas, manage backgrounds (color or image), and draw entities at specific positions. Multiple cameras can coexist on the same canvas, which allows you to create split-screen effects or complex interfaces.

The Camera class now supports advanced background features including:

  • Static and animated background images
  • Background image scrolling with velocity
  • Looped background images for seamless tiling
  • Customizable background fill styles
  • Frame rate stabilization for consistent rendering

ℹ️ Important: A camera must always be associated with a valid canvas element. Without a canvas, the camera cannot render elements.

🚀 Basic Usage

To create a camera, you need a canvas element and define its dimensions:

import { Camera } from "./jsge.js";

const canvas = document.querySelector("#gameCanvas");
const mainCam = new Camera({
    canvas: canvas,
    position: {x: 0, y: 0},
    dimensions: {width: 800, height: 600},
    backgroundColor: "#222"
});

Once the camera is created, you can start drawing elements:

// Clear the camera (do this every frame)
mainCam.clear();

// Draw an entity (after creating the entity)
entity.draw(mainCam);

📥 Constructor

The Camera class accepts the following parameters:

Parameter Type Default Description
options Object {} Configuration object for the camera. Required
options.canvas HTMLCanvasElement | string null The canvas element (or its ID) on which the camera will draw. Required
options.position {x: number, y: number} {x: 0, y: 0} Initial position of the camera in the scene (in pixels).
options.dimensions {width: number, height: number} {width: 100, height: 100} Width and height of the camera's rendering area.
options.backgroundColor string null Background color of the camera (e.g., "#ff0000", "blue", "rgba(0,0,0,0.5)").
options.backgroundImage string null Path to a background image (e.g., "./assets/background.png").
targetFPS number 60 Target frames per second for frame rate stabilization.

📊 Properties

canvas

Type: HTMLCanvasElement

Description: The canvas element associated with the camera.

ctx

Type: CanvasRenderingContext2D

Description: The 2D context of the canvas.

position

Type: {x: number, y: number}

Description: Position of the camera in the scene (in pixels).

dimensions

Type: {width: number, height: number}

Description: Size of the camera's rendering area.

backgroundType

Type: "color" | "image" | null

Description: Type of background: "color", "image", or null for transparent.

backgroundColor

Type: string | null

Description: Background color of the camera.

backgroundImage

Type: HTMLImageElement | null

Description: Background image element of the camera.

backgroundImageVelocity

Type: {x: number, y: number} | null

Description: Scrolling speed of the background image (in pixels per frame). Creates automatic parallax effect.

backgroundImageLoop

Type: boolean

Description: If true, the background image repeats in a loop (tiles seamlessly).

backgroundImageFillStyle

Type: "fill" | "imageSize" | null

Description: Fill style of the background image. "fill" stretches to camera dimensions, "imageSize" uses original image size.

backgroundImagePosition

Type: {x: number, y: number} | null

Description: Current position offset of the background image.

backgroundImageDimension

Type: {width: number, height: number} | null

Description: Dimensions used for background image rendering.

cacheCanvas

Type: HTMLCanvasElement | null

Description: Internal cache canvas used for background rendering optimization.

targetFPS

Type: number

Description: Target frame rate in milliseconds (1000/fps). Used for frame rate stabilization.

toleranceDelta

Type: number

Description: Tolerance in milliseconds for frame timing. Helps avoid requestAnimationFrame imprecision.

⚙️ Methods

clear()

Description: Clears the camera content by calling clearRect on the context. If a background is defined, it will be redrawn. This method also initiates a new frame for rendering. This method respects the target FPS and only clears when a new frame is needed.

Returns: void

drawCameraBorder(color)

Parameters:

  • color: string - The border color (e.g., "yellow", "#ff0000").

Description: Draws a colored border around the camera. Useful for debugging and visualizing camera boundaries.

Returns: void

moveCamera(newPosition, mode)

Parameters:

  • newPosition: {x: number, y: number} - The position offset to apply.
  • mode: "relative" | "absolute" - The movement mode.

Description: Moves the camera by an offset. In "relative" mode, the offset is added to the current position. In "absolute" mode, the offset becomes the new position. Note: this moves the camera and its content, not the viewport for scrolling.

Returns: void

flipBuffer()

Description: Processes the draw list and renders all queued elements. ⚠️ IMPORTANT: This method is NOT called automatically. You MUST call it manually after establishing the list of entities to draw. It sorts elements by z-order and renders them to the camera.

Returns: boolean - Returns true if a new frame was rendered.

// Proper usage: call flipBuffer() after adding all elements
mainCam.clear();
// Add entities to draw list
entity.draw(mainCam);
// Process and render the draw list
mainCam.flipBuffer();

_addToDrawList(elem, zOrder)

Parameters:

  • elem: Entity | Element - The element to add to the draw list.
  • zOrder: number - The z-order for rendering.

Description: ⚠️ PRIVATE METHOD: Internal method to add elements to the draw list. Not intended for direct use. Incorrect usage can cause engine crashes. Use public methods instead.

Returns: void

_addToDrawScene(scene)

Parameters:

  • scene: Scene - The scene to add to the draw queue.

Description: ⚠️ PRIVATE METHOD: Internal method used by Scene class to register scenes for drawing. Not intended for direct use. Incorrect usage can cause engine crashes.

Returns: void

🎨 Background Features

The Camera class provides powerful background management capabilities:

Static Background Color

const camera = new Camera({
    canvas: canvas,
    dimensions: {width: 800, height: 600},
    backgroundColor: "#166088"
});

Static Background Image

const camera = new Camera({
    canvas: canvas,
    dimensions: {width: 800, height: 600},
    backgroundImage: "./assets/background.png"
});

Animated Background Image (Parallax)

Create a scrolling background effect by setting the velocity:

const camera = new Camera({
    canvas: canvas,
    dimensions: {width: 800, height: 600},
    backgroundImage: "./assets/clouds.png",
    backgroundImageVelocity: {x: 1, y: 0},  // Scrolls right at 1px/frame
    backgroundImageLoop: true
});

// The background will automatically scroll

Tiled Background

Create a seamless tiled background:

const camera = new Camera({
    canvas: canvas,
    dimensions: {width: 800, height: 600},
    backgroundImage: "./assets/tile.png",
    backgroundImageFillStyle: "imageSize",  // Use original image size
    backgroundImageLoop: true  // Tile the image
});

Multi-Layer Parallax

Create depth with multiple cameras:

// Far background (slowest)
const bgFar = new Camera({
    canvas: canvas,
    position: {x: 0, y: 0},
    dimensions: {width: 800, height: 600},
    backgroundImage: "./assets/mountains.png",
    backgroundImageVelocity: {x: 0.1, y: 0}
});

// Mid background
const bgMid = new Camera({
    canvas: canvas,
    position: {x: 0, y: 0},
    dimensions: {width: 800, height: 600},
    backgroundImage: "./assets/trees.png",
    backgroundImageVelocity: {x: 0.5, y: 0}
});

// Near background (fastest)
const bgNear = new Camera({
    canvas: canvas,
    position: {x: 0, y: 0},
    dimensions: {width: 800, height: 600},
    backgroundImage: "./assets/grass.png",
    backgroundImageVelocity: {x: 1, y: 0}
});

function gameLoop() {
    // Clear and draw each layer
    bgFar.clear();
    bgMid.clear();
    bgNear.clear();
    
    requestAnimationFrame(gameLoop);
}

🎯 Examples

Example 1: Camera with Color Background

Use arrow keys to move the camera. 

import { Camera } from "./jsge.js";

const canvas = document.querySelector("#gameCanvas");
const mainCam = new Camera({
    canvas: canvas,
    position: {x: 0, y: 0},
    dimensions: {width: 800, height: 600},
    backgroundColor: "#222"
});

// Move camera with arrow keys
document.addEventListener("keydown", (e) => {
    const speed = 5;
    switch(e.key) {
        case 'ArrowRight':
            mainCam.moveCamera({x: speed, y: 0}, "relative");
            break;
        case 'ArrowLeft':
            mainCam.moveCamera({x: -speed, y: 0}, "relative");
            break;
        case 'ArrowDown':
            mainCam.moveCamera({x: 0, y: speed}, "relative");
            break;
        case 'ArrowUp':
            mainCam.moveCamera({x: 0, y: -speed}, "relative");
            break;
    }
});

function gameLoop() {
    mainCam.clear();
    // Draw your entities here...
    requestAnimationFrame(gameLoop);
}
gameLoop();

💡 Tips and Best Practices

  • 🎯 Always clear the camera every frame with clear() to avoid visual artifacts. This also initiates a new frame.
  • 🎯 Always call flipBuffer() after adding all elements to the draw list. This processes and renders all queued elements.
  • 🎯 Use multiple cameras to create split-screen effects or separate game from UI.
  • 🎯 For a game with scrolling, adjust the camera's position property directly to follow the player. Note: a dedicated scrolling method is planned but not yet implemented.
  • 🎯 Use backgroundImageVelocity and backgroundImageLoop to create animated backgrounds without additional code.
  • 🎯 Use drawCameraBorder() during development to visualize camera boundaries.
  • 🎯 For better performance, avoid creating too many active cameras simultaneously.
  • 🎯 The targetFPS parameter helps stabilize frame timing but doesn't limit the actual frame rate.
  • 🎯 Use backgroundImageFillStyle: "imageSize" for seamless tiling with the original image dimensions.
  • ⚠️ Avoid using methods starting with _ (underscore). These are private methods not intended for direct use. Incorrect usage can cause engine crashes.
